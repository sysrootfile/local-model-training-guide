The [Image LoRA Training](/en/gorsel/lora-egitimi/) page told the theory and the kohya pipeline; here we set up the same job end to end with **ai-toolkit**, one of 2026's tools: a script auditing the dataset **before** training, a ready SDXL LoRA config, and the trained LoRA's use in ComfyUI. ## 1) What are we doing?

The scenario: you have **15-30 images** drawn in your own style (e.g. watercolor, charcoal, a color palette unique to you) and you want to teach SDXL that style and generate in any scene you want. The pipeline has five stops:

```text
1. Data collection     2. Caption              3. Audit             4. Training             5. Use
15-30 images  ───►  same-named .txt  ───►  veri_kontrol.py  ───►  ai-toolkit   ───►  ComfyUI
(1024px+)             + trigger              (CPU, seconds)         (a YAML config)     LoraLoader
                                                                    └──► a LoRA .safetensors
```

The data rules (the details on the [Image LoRA Training](/en/gorsel/lora-egitimi/) page):

- **Count:** 15-30 images suffice; variety — angles, backgrounds, composition — matters more than the count.
- **Resolution:** the short edge at least 1024px (the SDXL standard). A small image is upscaled in training and teaches blur.
- **No repeats:** nearly identical frames shot side by side are really **one image**; the audit script in section 4 finds this automatically.
- **Captions:** a **same-named** `.txt` beside every image; a trigger word (e.g. `mystyle`) is added per caption. For automatic labeling **WD14 tagger**, **Florence-2** or **JoyCaption** can be used; generating with the machine label and correcting the final form by eye is the most efficient path.
- **Language:** SDXL's CLIP text encoder was trained mostly on English; writing the captions in English markedly raises the hit rate. The trigger word can stay Turkish — it should be a "meaningless" string anyway.

## 2) The base model and license choice

The base model decision also determines **where your LoRA can be used**: the base model's license binds your LoRA too. As of 2026 the landscape is:

| Base model | License | Approximate VRAM for training | Note |
| --- | --- | --- | --- |
| **SDXL** (base 1.0) | CreativeML Open RAIL++-M | 12 GB comfortable, 8 GB borderline | This project's choice: open to commercial use, the most mature tool support |
| Z-Image 6B | Apache-2.0 | ~16 GB | New generation; permissive, but the ecosystem isn't as broad as SDXL's |
| FLUX.2 klein 4B | Apache-2.0 | ~12 GB (quantized) | The FLUX family's small, permissively licensed version |
| Qwen-Image | Apache-2.0 | ~24 GB (quantized) | Strong in text/poster-heavy jobs; its official examples come under the "24gb" name |

Three reasons we started with SDXL: it's **open to commercial use** with an established license, it's the architecture the LoRA training tools (ai-toolkit, kohya, OneTrainer) support best, and at 1024px quality it fits this guide's VRAM budgets.

:::danger[A license warning: a LoRA trained with FLUX.2-dev can't be used commercially]
FLUX.2-dev is distributed under a **non-commercial** license. You can't use a LoRA you trained with the dev variant in a commercial job, or distribute it with a commercial product — even though you trained it — because the base model's license passes to your derivative work. If you have a commercial plan, choose FLUX.2 **klein** (Apache-2.0), SDXL (Open RAIL++-M) or one of the other listed Apache-2.0 models. If you'll share the model, also remember to write the base model and license on the model card: [Sharing on Hugging Face](/en/kullanim/huggingface-paylasim/).
:::

## 3) The setup: ai-toolkit

In this project the training side is done with **ai-toolkit** (the MIT license, [ostris/ai-toolkit](https://github.com/ostris/ai-toolkit)). It works with a YAML config and supports both SDXL and Flux LoRA training; it has a web UI too, but we'll use the command line. The official setup steps as of 2026:

```bash
git clone https://github.com/ostris/ai-toolkit.git
cd ai-toolkit
python -m venv venv
.\venv\Scripts\activate          # Windows
# source venv/bin/activate       # Linux

# PyTorch is installed first; the version and CUDA index change over time,
# take the command in the official README as authoritative:
pip install --no-cache-dir torch==2.13.0 torchvision==0.28.0 torchaudio==2.11.0 --index-url https://download.pytorch.org/whl/cu130
pip install -r requirements.txt
```

If you hit compilation problems on Windows, the community's easy-install script ([Tavris1/AI-Toolkit-Easy-Install](https://github.com/Tavris1/AI-Toolkit-Easy-Install)) reduces the job to a single button.

| Alternative tool | Interface | For whom |
| --- | --- | --- |
| ai-toolkit | A YAML config + web UI | This project's choice; supports SDXL and Flux in the same structure |
| OneTrainer | A desktop GUI | Those who like trying by clicking; a kohya-like experience |
| SimpleTuner | A YAML config | Advanced users; a broad model list and fine-tuning options |

:::tip[The data audit script wants no training environment]
The audit script asks only for Pillow and runs on any GPU-less machine. Auditing the dataset before preparing the training environment (the heavy setup above) lets you show the flaws in minutes, before a training that will take hours.
:::

A summary of the config's critical values:

| Setting | Value | Why this value? |
| --- | --- | --- |
| `linear` (rank) | 32 | Enough capacity for SDXL style work; 16 weak, 64 an unnecessarily big start |
| `linear_alpha` | 32 | ai-toolkit's official examples use alpha=rank |
| `lr` | 1e-4 | The typical start for SDXL LoRA; the first value to lower if the sample images break |
| `steps` | 1500 | The middle of the 1000-2000 range for SDXL style; you can return to an early checkpoint with the intermediate saves |
| `resolution` | 1024 | The resolution SDXL was trained at; other ratios are bucketed automatically |
| `save_every` | 250 | The way to catch overfitting early: test the intermediate files while training runs |
| `train_text_encoder` | false | Training the text encoder on SDXL seriously grows VRAM and is usually unnecessary for style |
| `noise_scheduler` / `sampler` | `ddpm` | The two must match; SDXL's noise program is ddpm |

## 6) Training and monitoring

When the config is ready, training starts with one command (from the ai-toolkit repo's root):

```bash
python run.py config/stilim-sdxl-lora.yaml
```

The outputs are written under `output/` with the session name:

```text
ai-toolkit/output/stilim-sdxl-lora-v1/
├── *.safetensors    → the LoRA saves (an intermediate save every save_every: 250 + the final save)
└── sample images    → the test generations produced while training runs
```

The file name pattern can change by ai-toolkit version; what matters is the LoRA file with the `safetensors` extension — that's the only thing going to ComfyUI. You can stop the training with `Ctrl+C` and continue with the same command; but if you cut it **at the moment of saving**, that checkpoint corrupts (the official README's open warning).

**What will you see in the training log?** Lines containing the step number and the loss value flow in the terminal at regular intervals; since the exact shape varies by version we're not putting a sample log here — training wasn't run on this page. While watching, read two sources together:

| What's watched | What's looked at |
| --- | --- |
| The loss lines | Is it dropping, is it oscillating? A convergence to zero isn't good news, it can be a memorization sign |
| The sample images (every 250 steps) | The intermediate saves' generations are compared with the same prompt and a fixed `seed` |

:::caution[Trap 1: overfitting]
While watching, these three signals show memorization: (1) if the generations approach copies of the training images, (2) if the scene doesn't change even when you change the background, (3) if the style forcibly appears in every generation even without the trigger word. The fix is one: **return to an earlier intermediate save.** An undertrained LoRA can always be rescued; an overtrained one can't. That's why we keep `save_every: 250` and the steps at 1500 — we dug into the theory on the [Image LoRA Training](/en/gorsel/lora-egitimi/) page.
:::

:::caution[Trap 2: caption quality]
The training learns over "the part of the image the caption **doesn't describe**", not "the whole image". A triggerless caption makes binding the style to the word impossible (like `sahne_06.txt` in section 5). An overly detailed or wrong caption mixes content with style. The golden rule: **label what you're teaching, leave the rest to the model's knowledge.**
:::

:::note[Trap 3: the license]
A small but expensive mistake: training FLUX.2-dev with an 8 GB card may be technically possible, but that LoRA can't be used commercially (see section 2). If VRAM is tight, first budget with the tables on the [VRAM Math](/en/donanim/vram-hesabi/) page, and if it's not enough, evaluate a rented GPU from the [Cloud Options](/en/donanim/bulut-secenekleri/) page.
:::

## 7) Use in ComfyUI

When training finishes you'll have a single `.safetensors` file on the order of MBs. In ComfyUI, three steps:

1. Copy the file into the `ComfyUI/models/loras/` folder.
2. Add the **LoraLoader** node between the Checkpoint Loader (SDXL base) and the KSampler; chain the `model` and `clip` inputs.
3. Set the strength (weight) to **0.8** initially; sweep and compare across the 0.6-1.0 range.

The test prompt must definitely contain the trigger word:

```text title="an example test prompt (CLIP-based SDXL understands English)"
mystyle, watercolor landscape, misty mountains and a lake, pastel colors
```

When testing, ask two questions:

- **The generalization test:** ask for scenes never seen in training (another season, a crowded city); if the style still comes, the model hasn't memorized, it has learned.
- **The triggerless test:** if the style appears even without writing the trigger, it may be overtrained; return to an earlier checkpoint.

The LoRA doesn't run alone; it's a **patch** applied on top of the SDXL base. If you want to load it and make it permanent (to carry as a single file), the method on the [LoRA Merging](/en/kullanim/lora-birlestirme/) page does the job — the merged model also carries the base model's license.
